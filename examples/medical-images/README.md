# Medical image benchmark generation

Build tasks over an authorized image repository using a field, task profile,
model input/output contract, and evaluation criteria. This track is broader than
ReXrank. The first executable profiles are single-label classification and
closed-answer visual questions. They can share images, but retain distinct
metrics. Questions are generated over existing acquired images. Image acquisition,
clinical labels and expert review are not generated by this workflow.

## Run a repository-backed benchmark

Install this branch/release with `pip install -e '.[imaging]'`. Configure a funded
vision provider using the existing LiteLLM environment variables. For example,
OpenRouter routes use `OPENROUTER_API_KEY` and model names prefixed with
`openrouter/`. Use a new private output directory for every prospective run.

```sh
python -m arisekit.images.image_generation connect-medmnist /tmp/image-run --dataset breastmnist --size 224 --count 4 --positive-class malignant --authorize-source-and-provider
python -m arisekit.images.image_generation freeze /tmp/image-run examples/medical-images/brief.json
python -m arisekit.images.image_generation run /tmp/image-run
python -m arisekit.images.image_generation status /tmp/image-run
```

`run` automatically performs generation, independent AI review and paired solver
evaluation until complete or stopped. Rerun it to continue retained work.
`advance` remains available for a single step. Successful calls are retained and
reused. A stopped `run` exits with status 1 after reporting its retained state. A dispatch
with an uncertain outcome stops instead of being sent again. Keep failed runs;
changing a source, brief, model role or runtime requires a new run.

The connector supports BreastMNIST at 28, 64, 128 and 224 pixels (CC BY 4.0), and
DermaMNIST at 28 and 64 pixels (CC BY-NC 4.0). It verifies the official release's
byte size and MD5 from Zenodo 10519652 and retains SHA-256. The default sample
cycles across included classes in a seeded order, then selects deterministically
within each class. `--sampling hash` selects by seeded hash alone. This small,
class-balanced sample changes the released class prevalence; its accuracy is
descriptive for the selected tasks. The manifest retains indices and class counts.
`--include-class` can restrict selection using exact released class names.
Repeat `--exclude-index` to exclude previously used release indices before sampling.
For example:

```sh
python -m arisekit.images.image_generation connect-medmnist /tmp/derma-run --dataset dermamnist --size 64 --count 4 --include-class melanoma --include-class 'melanocytic nevi' --positive-class melanoma --authorize-source-and-provider
```

Use `--archive /path/to/release.npz` to reuse an exact verified official archive.
The connector converts pixels to PNG without changing labels. BreastMNIST retains
the released malignant versus combined normal/benign mapping; it does not infer
normal versus benign sublabels. DermaMNIST retains its seven-class taxonomy even
when source selection includes fewer classes. Source patient IDs are absent, so the entire
selected cohort is a single conservative group and `evaluation_fraction` must be
1. This prevents an unsupported source/evaluation patient-separation claim;
it does not independently verify patient identities. The original and generated
arms intentionally use the same selected images and reference labels. The
connector supplies a fixed natural-language baseline question for the released
classification task; this wording is an ARISEKit adapter choice, not an official
MedMNIST language-model prompt.

The writer is instructed to ask questions answerable from the image and choices
alone. Original wording and earlier generated stems are excluded from its input.
For classification, writer and AI critic see the taxonomy without the item answer,
annotation evidence or source index. This prevents question wording from depending
on a private reference. The critic assesses question construction and the image;
code retains and checks the unchanged source references. Other profiles retain
their separate private-evidence policy. Critic findings remain recorded judgments,
not a claim of completed expert review.

Image packages retain the solver instruction, temperature and output-token limit.
`Benchmark.from_package` restores these settings and rejects conflicting overrides.
This makes default shared-runner requests match the paired evaluation. Older image
packages without this contract retain their previous loading behavior.

## Run bounded development cycles

The product is the generator. Benchmarks supply development feedback and
independent evaluation material; generated packages are outputs of that process.
Improve reusable generator behavior and global criteria, retaining every output.
Do not hand-edit items to make a particular generated set score better.

Declare `evaluation_role: "development"` and a `question_styles` list using one
or more of `direct`, `selection`, `assignment`, and `classification`. This is
the classification profile. Every image receives every declared
style. Original questions are repeated equally often, so comparisons average
the same number of answers in both arms. The writer receives the public taxonomy
and style without image pixels, item references, source indices or original wording.

```python
from arisekit.images.image_iteration import run_development_cycles

result = run_development_cycles(
    "/private/image-cycles", source="/private/development-source",
    brief=development_brief, generator=writer, critic=critic, solvers=solvers,
    rounds=3, max_cost=2.25,
)
```

The brief's `max_cost` is the allowance for each round, including its preceding
AI revision proposal. For the example above, use `max_cost: 0.75` and
`max_cost_per_call: 0.025`. Set `max_calls` to cover all images, forms and models.
The cycle checkpoints each call, records diagnosis, obtains criteria for the
next prospective round, and retains every candidate. It selects the generator
with the fewest lost stable-original comparisons, then mean absolute calibration
error, then maximum error. The earlier calibration-first choice stays visible.
A candidate must provide distinct forms without original copies; original-informed
candidates also exclude prefix-only copies. If every round fails these wording
requirements, the cycle returns `no-eligible-candidate` with all diagnoses and
costs, and exports no generator policy. Rerunning identical inputs resumes without repeating completed calls.
Use `evaluation_role: "holdout"` for a locked evaluation; revision and development
selection reject that role. No item is edited after its outputs are observed.
Calibration, rank preservation, repeated-form variation and lexical diversity
remain separate reported outcomes.

The automatic cycle uses `select_comparison_preserving_revision` from
`arisekit.images.image_selection`. It can also be applied to completed development roots. It derives consistently ordered model pairs from
all original repeats, then prioritizes retaining those comparisons before
minimizing calibration error. It requires distinct requested forms and no exact
normalized original matches for this study's novel-question selection. It keeps
the calibration-first choice and all candidates visible. Freeze the resulting
choice before evaluating holdouts; neither selector accepts holdout runs.
Selection uses exact correct/assigned counts to preserve pooled ties. Freeze
the selected generation runtime as well as its criteria; when source changes,
running old criteria through the new writer is a different candidate. Offline
reports can read checksummed historical runs and disclose a runtime mismatch,
while paid dispatch still requires the frozen runtime. AI proposals and reviews
remain retained even when their wording conflicts with declared styles.
New plans freeze their public vocabulary and simple form rules. Reports check
literal violations separately from AI alignment, and subsequent revision feedback
includes those counts and the immutable rules. Historical plans without frozen
rules report that absence; current rules are not imposed afterward.

### Freeze and reuse the generator

A successful cycle exports `generator-policy.json` and its SHA-256 receipt. This
is the reusable generator: learned criteria, forms, task profile, authoring model
routes and exact engine identity. Source items, answers, solver rosters, field,
modality, seeds, splits and budgets stay in the separate evaluation plan.

```python
from arisekit.images.image_policy import apply_image_generator, load_image_generator
from arisekit.images.image_generation import freeze_images

policy = load_image_generator('/private/image-cycles/generator-policy.json')
evaluation = apply_image_generator(policy, heldout_brief)
freeze_images('/private/new-source-evaluation', evaluation)
```

Ingest the new source under `/private/new-source-evaluation/source` first. Its
brief declares the held-out role, field/modality selection, solver panel, input
controls and execution limits. It can omit criteria, question forms, authoring
models and task profiles; the policy supplies them. If task profiles are supplied,
they must match. Applying the policy preserves the evaluation controls. Paid generation still uses `run_images` and its
existing checkpoints. The new plan and report carry the same generator identity.
Changing its criteria, authoring routes, styles or engine requires a new identity;
a different dataset or solver panel does not. Use the saved engine for a frozen
policy. The checksum binds data, not trusted code execution or clinical validity.

The artifact records development lineage by hash without copying training cases
or scores. A complete local transfer through another synthetic source tests this
separation; it is engineering evidence, not medical generalization evidence.
The current generator still varies question wording over existing source images
and references. Clinical task preservation, held-out comparison recovery and
conceptual novelty remain separate empirical outcomes.

### Use native clinical image questions

The local VQA-RAD adapter keeps original questions, source answers, public semantic
frames and human paraphrases separate. It pins the official question snapshot
and checks individual image hashes against cached official OSF file metadata.
Its bounded pool contains closed yes/no test-paraphrase rows marked strict
agreement with a human paraphrase and frame. It does not cover open-answer VQA.

```python
from arisekit.images.vqa_rad import candidates, connect_vqa_rad

pool = candidates('/private/VQA_RAD Dataset Public.json')
connect_vqa_rad('/private/vqarad-run/source',
    snapshot='/private/VQA_RAD Dataset Public.json',
    image_index='/private/osf-images.json', question_ids=[31, 34],
    cache_dir='/private/vqarad-image-cache')
```

Use `profiles: ["closed-vqa"]` and styles `clinical-direct` and
`clinical-rephrase`. Every selected target must declare a public semantic frame.
The writer then receives that frame and style without pixels, item answers,
original questions or human paraphrases. The critic receives the image and frame
without those reference fields. The original solver arm uses the native question
with standardized finite-answer instructions. Source human paraphrases can be
evaluated separately as a wording control; they do not fill new expert ratings.
Classification styles cannot silently enable this evidence policy for legacy
VQA annotations.

Set `original_question_access: true` explicitly to give the writer and critic
the public original question as the authoritative task definition. This option
requires styled closed yes/no tasks. The frame becomes a secondary aid; source
answers and human paraphrases stay hidden, and the writer still receives no
pixels. Reports distinguish prefix-only original copies from different grammar.
Original-informed candidates cannot qualify as novel merely by adding the
required image-context opening. Revision feedback also reports task-type
coverage so a mixed question set is not reduced to presence questions.

Set `copy_repair_attempts: 1` prospectively for styled closed-VQA generation with
explicit original-question access. A deterministic check uses the existing exact
and image-prefix copy definitions. Only detected copies receive one writer rewrite;
other checks skip without a model call. Initial responses, decisions, rewrites and
remaining copy failures stay retained. Critics, solvers, packages and diagnostics
use the final question; no source answer or choice changes. The flag is part of
the reusable generator identity. Default zero preserves the existing workflow.

Reserve one potential repair step per question in `max_calls`; actual provider
calls exclude skipped checks. Set `transport_retries: 0` when uncertain paid calls
must not be repeated. A rewrite is a new, bounded authoring step on a completed
candidate, not a retry of an uncertain provider request. Clinical task preservation
still requires independent post-freeze evaluation.

`clinical-alternate` is an opt-in closed-VQA style that permits natural grammar
without a mandatory opening or auxiliary conversion. It still requires a novel
predicate or clause structure, an unchanged yes/no decision and no added findings.
Its questions must end with a question mark; exact and image-prefix copies remain
reported and cannot qualify a selected original-informed generator.

`candidates(snapshot, source_policy="original-question")` and the same explicit
option on `connect_vqa_rad` use released `freeform` original yes/no items. This
mode preserves the original source answer and uses the original question itself
as the public task frame. It requires `original_question_access: true` at freeze,
provides no source-human paraphrase control and makes no new expert-validation
claim. The default paraphrase-frame pool and its historical protocols are unchanged.

The small-subset language-model experiment is not the full
MedMNIST classification protocol. It returns discrete labels and reports accuracy;
it does not produce class probabilities or claim MedMNIST AUC comparability.

`--positive-class` adds a deterministic yes/no class-membership target while
preserving the classification target. Its reference records the rule, parent
target, parent provenance kind and reference digest. It shares the same annotation
fact and image as classification; it is not an independently annotated VQA dataset.
When both profiles are evaluated, the comparison reports logical contradictions
between the model's class prediction and its class-membership answer. The legacy
`connect-breastmnist` command keeps its original 28-pixel hash-sampling behavior.

## Generate from your images and labels or reports

Upload a flat folder of authorized PNG/JPEG images with a per-image evidence file.
Every image requires supplied labels or a report. Users do not need to write
benchmark questions. Labels specify the clinical task, finite choices, exact
answer and provenance. Reports supply text and provenance; answers derived from
reports are recorded as AI interpretations with exact supporting excerpts.

```sh
python -m arisekit.images.image_upload freeze /approved/images examples/medical-images/upload-brief.json /private/upload-run --evidence /approved/evidence.json --source-name "My image collection" --license "Institution-approved research use" --authorize-source-and-provider
python -m arisekit.images.image_upload run /private/upload-run
python -m arisekit.images.image_upload status /private/upload-run
```

Use `upload-evidence.example.json` as the evidence shape, replacing its filenames,
labels, report and provenance with actual supplied evidence. Each image needs at
least one label or a report; it can have both. `label-1`, `label-2`, etc. bind tasks
to the corresponding supplied labels. The generator cannot change a label's
choices or answer. A `report` binding requires an exact supporting report excerpt;
it remains AI interpretation even when the upstream report is clinician authored.

`/private/upload-run/benchmark` is a runnable MAST-compatible image package.
`upload-report.json` retains assigned/completed solver counts and independent AI
review. The reviewer receives label definitions with answers withheld, or report
text, plus the image and generated question. Disagreements do not replace primary
references or exclude tasks. New expert validation remains separate from the
provenance of existing source labels and reports.

Every supplied image is included; the call limit must
cover one writer request per image, one independent review per task, and every
solver/task. Execution checkpoints each response and stops on unknown cost with
zero retry. Limits are 2–200 PNG/JPEG images, 5 MB per image and 10 MB total.
DICOM/volume conversion and image de-identification remain external inputs.

## Upload or connect an annotated collection

Place `source-manifest.example.json` beside its referenced images, replace the
illustrative source metadata and annotations with authorized source evidence,
then run:

```sh
python -m arisekit.images.image_generation ingest /approved/source/manifest.json /private/image-run
python -m arisekit.images.image_generation freeze /private/image-run /private/brief.json
```

Each record contains a pseudonymous `id`, `group_id`, `group_basis` (`patient`,
`case`, or `conservative-cohort`), field, modality, optional selection tags,
1–4 flat PNG/JPEG filenames, and one or more targets. Each target supplies an
original question, supported profile, 2–30 distinct answer choices, one exact
source answer, source evidence, and reference provenance (`dataset-annotation`,
`expert`, `ai`, or a verified `derived-annotation`). AI ancestry remains explicit
when a deterministic reference derives from an AI parent. Do not convert
unknown findings into invented source labels. A collection without suitable
annotations must obtain those through a separate authorized reference workflow.

Images are decoded before dispatch. Missing, corrupt, truncated, oversized,
unsupported and mismatched-format assets fail explicitly. The local limit is
10 MB per collection and 5 MB per image. Storage uses SHA-256 filenames and
private directory/file permissions. Original filenames and patient identifiers
are not sent to the models. Source metadata and annotations remain sensitive
even when filenames are pseudonymous; institutional IT owns de-identification.

Splits are deterministic by seed and connected groups. Patient/case identifiers
and exact decoded-pixel duplicates are joined before splitting. A patient/case
cannot cross the split when its supplied group identifier is correct. A
conservative cohort stays together. The manifest records the basis of grouping;
case grouping does not establish patient independence. Near-duplicate perceptual
hash distances are reported as diagnostics, not clinical duplicate verdicts.
Reserved source groups never enter generation or solver requests. Generating a
an image-grounded question exposes that image to the writer; the styled
classification mode instead supplies only the public taxonomy and style.
Neither workflow is a held-out image-training experiment.

Field, modality and tags determine eligible records. Each selected record must
have every requested profile. When a record has multiple targets for a profile,
choose explicit `target_ids` in the brief; the browser shows target questions and
their record coverage. All selected compatible targets become tasks. The workflow
does not silently choose the first annotation. Free-text criteria reach the writer and independent
critic verbatim. Selection freezes before responses or scores exist. The writer
can change question wording, but cannot replace the source target, choices or
answer. The critic sees the image and permitted task evidence, and reports grounding,
criteria alignment, issues and uncertainty. Its judgments do not become expert
review or a clinical validity gate. A failed structural response remains retained;
the current slice does not automatically repair it.

## Evaluation and export

Both arms send actual base64 image blocks to the configured vision model. Solver
payloads contain only the question and images, with no source answer or review.
Generation and review calls also receive the images. Raw normalized responses,
image hashes, tokens, provider identifiers, timing, cost and uncertain charges
are retained. Empty outputs, invalid vocabulary, missing results and provider
errors are explicit. All assigned tasks remain in the comparison denominator.

`classification_accuracy` and `closed_vqa_accuracy` use exact finite-answer
matching after Unicode/case/whitespace and terminal-punctuation normalization.
Negation, alternative choices and explanations do not silently match a label.
The package preserves references and scorer identity for deterministic re-scoring.
Duplicate question wording is reported separately from duplicated image/task pairs.
Question duplication, exact original matches and token overlap are diagnostics;
they do not establish conceptual novelty. Shared images/cases are not independent
observations. The initial comparison is descriptive and paired, without a numeric
similarity gate or claim of clinical equivalence.

### Check image-input dependence

Set `image_controls` to `["question-only", "contrasting-image"]` in a prospective
brief, or select these controls in the browser. `brief-controls.json` supplies a
four-case, two-profile, one-solver example with a 64-call limit:

```sh
python -m arisekit.images.image_generation connect-medmnist /tmp/image-controls --dataset breastmnist --size 224 --count 4 --seed medical-images-v3-controls --positive-class malignant --authorize-source-and-provider
python -m arisekit.images.image_generation freeze /tmp/image-controls examples/medical-images/brief-controls.json
```

Question-only controls omit every image block while retaining the same system
prompt, question and vocabulary. Contrasting-image controls replace the images
using another selected task with the same source question, target ID, field,
modality and image count, a different source answer, and disjoint decoded pixels.
The donor is chosen deterministically before generation or scoring. Reserved
source groups are never donors. Missing compatible donors are reported as
unavailable; no alternative task or image is invented.

Each model answers both arms under matched images and the chosen controls.
Every assigned step receives its own retained request, including identical
question-only prompts. Retrying the same step reuses its confirmed response.
Control results report agreement with the original reference, agreement with the
donor reference where applicable, prediction changes across valid pairs, and
assigned, unavailable, invalid and missing counts. These results stay separate
from primary classification/VQA accuracy. A donor-appropriate answer can disagree
with the original reference; that is an input-control observation, not an error
in the correctly bound benchmark package. The packages keep their correct images;
control bindings and responses remain in the complete run archive.

The design follows the motivation for testing the same question against images
with different answers in [Goyal et al., CVPR 2017](https://openaccess.thecvf.com/content_cvpr_2017/html/Goyal_Making_the_v_CVPR_2017_paper.html).
This implementation uses released medical-image labels and conservative source-task
matching; it does not reproduce that dataset's human-curated image pairing.
Single responses can vary even at temperature zero. Small descriptive controls
alone do not establish causal image use, clinical correctness or benchmark quality.

Each run exports `original/` and `generated/` as verified ARISEKit packages with
image bindings and a bound scorer. Load them with `Benchmark.from_package` or:

```sh
arisekit run-package /private/image-run/generated --model openrouter/openai/gpt-4o-mini
```

Use `arisekit.runtime.distribution.export_benchmark` for a portable distribution and MAST
contribution handoff; pass a concise `description` for the selected task design.
The shared runner retains response checkpoints and score
outputs. MAST receives the ordinary dataset/scorer adapter, not a fabricated
ReXrank/GREEN score. Do not publish private source bytes in a benchmark repository.

## Add another profile

Add only the task contract needed by the implemented workflow. For another
finite-answer profile, define its annotation shape and metric in
`arisekit.images.imaging`, validate its input/output/reference contract, add meaningful
scorer perturbations and negative controls, and provide an authorized source
connector or upload example. Update the task selector and documentation.

Do not add report generation, open-answer VQA, localization, segmentation,
multi-label classification, ordinal grading, DICOM or 3D inputs merely as aliases
of this scorer. Report generation needs a release-bound report reference and
report-specific evaluator. Localization needs coordinates, frame conventions and
spatial scoring. Open VQA needs explicit equivalence/alias or independently
accounted semantic judgment. Multi-label and probabilistic tasks require their own
output contracts and metrics. Reuse the source store, split, ledger and image
delivery after those contracts exist.

## Design sources

- [MedMNIST official repository](https://github.com/MedMNIST/MedMNIST),
  [source label/release metadata](https://github.com/MedMNIST/MedMNIST/blob/main/medmnist/info.py),
  and [MedMNIST v2 paper](https://doi.org/10.1038/s41597-022-01721-8):
  classification designs and released data/label semantics.
- [VQA-RAD primary paper](https://doi.org/10.1038/sdata.2018.251): visual
  questions span several kinds of image understanding; closed/open answers
  should not inherit report-generation scoring. This implementation is a bounded
  closed-answer profile, not a claimed reproduction of VQA-RAD.
- [ReXrank official repository](https://github.com/rajpurkarlab/ReXrank) and
  [GREEN official repository](https://github.com/Stanford-AIMI/GREEN): report
  generation is a separate imaging benchmark pattern. The local MAST checkout's
  released ReXrank loader/scorers were inspected; they are not substituted for
  classification or VQA evaluation.

## Validate generated measurements

Use a prospective pilot protocol
to compare a frozen local model panel while keeping source labels and scoring fixed.
The writer receives annotations without original question wording. Local runs
accept up to 20 solver routes.
`connect_medmnist(..., exclude_indices=[...])` records exclusions before selection.

After generation and evaluation, create a fresh offline evidence directory:

```sh
python -m arisekit.images.image_validation /private/image-run /private/validation
```

The report preserves assigned denominators, ties, incomplete model data and
undefined bootstrap draws. It includes per-model paired differences, Kendall
tau-b, Lin's CCC, shortcut baselines, and available image-input controls. Source
group resampling stays unavailable for a single unresolved cohort. The analysis
makes no provider calls and does not declare equivalence.

The reviewer ZIP contains an interleaved ratings table with opaque item/image
IDs. Its private arm/reference mapping remains outside the ZIP. Experts answer
independently and record ambiguity, unsupported findings and provenance guesses.
Ratings start blank; AI content review does not fill the expert reference standard.


## Compare generator versions with complementary diagnostics

`generation_report` adds Spearman rho, OG-directed Somers D, tie-aware RBO-a,
reference-weighted Kendall tau, tie-inclusive top-k sets, ICC(A,1), empirical
TDI and optional coverage/Deming estimates. All are per-model score comparisons.

```python
from arisekit.images.image_validation import generation_report

report = generation_report(
    "/private/completed-image-run",
    analysis={"rbo_p": 0.9, "tdi_probability": 0.9},
)
```

Settings and their digest are retained in the report along with the analysis
source digest. Coverage is omitted until `coverage_tolerance_pp` is supplied;
Deming requires `deming_error_ratio` (generated/OG error variance). These are
exploratory diagnostics, with no new acceptance gate or change to selection.
The offline CLI accepts the same settings through `--analysis-config settings.json`.
Choose a fresh output directory to preserve previous evidence. This performs no
model calls. Passing–Bablok and the Study 2 categorical measures are planned,
not calculated by this release.


## Bound transient transport recovery

Local briefs can prospectively set `transport_retries` to 1 or 2; the default is
0. This reuses the shared dispatch ledger's reserve-based recovery for standard
`Timeout`, `TimeoutError`, `RateLimitError` and `ServiceUnavailableError` failures.
Each failed attempt consumes its declared per-call reservation and counts toward
both the total call limit and the per-request attempt limit. Recovery waits five,
then ten seconds. It cannot bypass the total budget or reset attempts on resume.
Pending interruptions, unclassified failures and successful responses with unknown
costs still stop execution. Privacy policy and provider routing are unchanged.

The cycle reserves `(transport_retries + 1) * max_cost_per_call` for each global
criteria proposal, with the original per-call bound kept separate. Allow enough
room for that proposal and model execution within each round. A completed run can
retain `cost_unknown: true` from recovered failures: its cost includes those
conservative reservations. Report this explicitly; full scored data do not make
the underlying provider charge known. Earlier frozen zero-retry studies keep
their original execution policy.
